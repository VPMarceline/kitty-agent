# 用户数据库

默认数据库文件为 `users.db`，由后端第一次启动时自动创建。可以通过环境变量 `USER_DATABASE_PATH` 修改位置。

## 数据表

- `users`：邮箱、显示名称、scrypt 密码哈希、创建时间和最后登录时间。
- `sessions`：随机会话令牌的 SHA-256 哈希、关联用户和过期时间。
- `agent_profiles`：每个用户独立的小猫名称、毛色和定制头像。
- `conversations`：每个用户的独立对话容器。
- `messages`：对话消息、安全标记、RAG 引用来源和创建时间。
- `conversation_summaries`：旧对话压缩摘要和已摘要到的消息位置。
- `user_memories`：用户明确要求 Agent 长期记住的信息。

Agent 资料和消息始终通过登录用户 ID 查询。前端只提交当前的新消息，历史上下文由后端从该用户的会话中读取，避免用户在请求中指定其他人的 Agent 或历史记录。

后端保留最近消息原文作为短期上下文；未摘要消息达到阈值后，会使用本地模型压缩较旧部分。长期记忆仅在用户明确说“请记住……”或通过记忆 API 添加时写入，并拒绝保存常见凭据和证件信息。用户可以清除长期记忆与摘要，且清除位置之前的旧消息不会重新进入后续摘要。

密码原文和会话令牌原文不会写入数据库。`users.db`、WAL 和 SHM 文件已加入项目根目录的 `.gitignore`，不要把它们提交到 Git。

## 开发环境

在 `server` 目录启动后端：

```powershell
npm run dev
```

在 `client` 目录启动前端：

```powershell
npm run dev
```

浏览器通过 Vite 的 `/api` 代理访问后端，认证 Cookie 不需要暴露给前端 JavaScript。

## 生产环境

- 必须使用 HTTPS，否则生产环境的 Secure Cookie 无法正常工作。
- 数据库文件需要定期加密备份，并限制为后端服务账户可读写。
- SQLite 适合单服务器和初期用户量；需要多个后端实例时应迁移到 PostgreSQL，并使用共享的限流与会话存储。
- 正式开放注册前还应增加邮箱验证、找回密码、账户删除、隐私政策和审计日志。
